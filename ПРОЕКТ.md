# POOLROOMS — устройство проекта

Игра про затопленные лиминальные пространства на three.js, редактор уровней,
общая таблица результатов, сетевая игра на 8 человек и панель сервера.

**Живёт тут:** https://poolrooms.ostrov-vezeniya.ru/
(порт 8083 наружу закрыт — только через HTTPS и центральный прокси)

---

## Как устроен репозиторий

```
src/core/      движок: сетка уровня, коллизии, вода, пост-обработка, материалы
src/game/      игра: игрок, монстры, звук, сеть, гироскоп, сенсор, счёт
src/editor/    редактор уровней
src/server/    панель сервера (обычный HTML, без сборки)
deploy/ostrov/ всё для боевого сервера: nginx, compose, api, realtime
assets/        музыка (в git не нужна, но нужна на сервере)
build.mjs      сборка: esbuild инлайнит весь JS внутрь HTML
```

**Правим только `src/`.** Потом:

```bash
npm run build     # соберёт game.html, editor.html, server.html
```

`game.html` и `editor.html` самодостаточны — открываются двойным кликом без
сервера. Музыка лежит отдельным файлом: три мегабайта в base64 раздули бы
страницу вчетверо, а gzip на сжатом звуке бесполезен. Нет `assets/` — просто
нет музыки, игра работает.

## Выкладка

```bash
scp game.html editor.html server.html ostrov:/var/www/poolrooms/
```

Если менялись `api/`, `realtime/`, `nginx.conf` или `docker-compose.yml`:

```bash
scp deploy/ostrov/nginx.conf deploy/ostrov/docker-compose.yml ostrov:/var/www/poolrooms/
scp deploy/ostrov/api/server.py ostrov:/var/www/poolrooms/api/
scp deploy/ostrov/realtime/server.js ostrov:/var/www/poolrooms/realtime/
ssh ostrov 'cd /var/www/poolrooms && docker compose up -d --build'
```

## Что крутится на сервере

Три контейнера из одного compose в `/var/www/poolrooms/`:

| контейнер | что делает | наружу | простой |
|---|---|---|---|
| `poolrooms-web` | nginx: статика + прокси на api и realtime | `172.17.0.1:8083:80` | 3.6 МБ, 0% |
| `poolrooms-api` | Python без зависимостей: таблица, вход, статистика | нет | 15 МБ, 0.02% |
| `poolrooms-realtime` | Node + ws: комнаты и ретрансляция | нет | 13 МБ, ~1.3% |

Наружу смотрит только `web`. Домен приходит через центральный прокси
`/srv/infrastructure/proxy.conf` → `172.17.0.1:8083`.

### Данные

Всё в `/var/www/poolrooms/data/scores.json`: строки таблицы, пользователи
(имя → соль и хеш PIN, самого PIN нигде нет) и счётчики забегов по дням.
Переживает `docker compose down`. Онлайн и комнаты живут только в памяти.

### Секреты

`/var/www/poolrooms/.env`, права 600:

- `ADMIN_TOKEN` — очистка таблицы (`DELETE /api/scores`)
- `STATS_PIN` — пароль панели и выключатель сетевой игры (значение в `.env`, в репозиторий не коммитим)

## Ручки API

Всё под `/api/` (Python) и `/ws/` (Node).

| метод | путь | доступ | зачем |
|---|---|---|---|
| GET | `/api/scores` | открыто | таблица результатов |
| POST | `/api/scores` | имя + PIN | записать забег |
| GET | `/api/players` | открыто | список имён для экрана входа |
| POST | `/api/auth` | имя + PIN | вход: занять имя или подтвердить |
| POST | `/api/ping` | открыто | «я в игре», для счётчика онлайна |
| GET | `/api/stats` | `X-Stats-Pin` | нагрузка, онлайн, забеги, комнаты |
| DELETE | `/api/scores` | `X-Admin-Token` | очистить таблицу |
| GET | `/ws/health` | открыто | состояние комнат |
| POST | `/ws/control` | `X-Stats-Pin` | включить/выключить сетевую игру |
| WS | `/ws/` | — | сама сетевая игра |

Ограничения: 40 записей результата в час с адреса, 12 неудачных PIN в час.
PIN хранится хешем (pbkdf2, 120 тысяч итераций, своя соль на каждого).

## Сетевая игра

Первый уровень из трёх: сервер раздаёт, кто где, но миром не владеет —
**монстры у каждого свои**. Общие твари, артефакт и приманка — следующий шаг,
три-пять дней; транспорт под него уже готов.

- **8 игроков в комнате, 8 комнат.** Комната — это уровень: кто выбрал
  «Затопленный вестибюль», видит таких же. Две разные компании на одном уровне
  окажутся вместе — если нужны независимые партии, надо добавить код комнаты.
- **Лобби.** Ведущий — первый вошедший, может начать не дожидаясь остальных.
  Ушёл ведущий — роль переходит следующему. Поздний игрок входит сразу в игру.
- **Аватары** с ником над головой, палитра на восемь заведомо различимых цветов.
  Таблички видны сквозь стены — в лабиринте иначе не найтись.
- 15 рассылок в секунду, интерполяция с отставанием 120 мс.
- Выключатель в панели сервера гасит саму игру (комнаты закрываются), но не
  процесс: управлять Docker из веба намеренно не даём, для этого пришлось бы
  отдать контейнеру сокет демона — это фактически root на машине.

Погасить процесс целиком, если всё же нужно:

```bash
ssh ostrov 'cd /var/www/poolrooms && docker compose stop realtime'
ssh ostrov 'cd /var/www/poolrooms && docker compose start realtime'
```

Игра, таблица и вход при этом продолжают работать — отвалится только сеть.

## Грабли, на которые уже наступили

**Гироскоп только по https.** `DeviceOrientationEvent` не существует в
незащищённом контексте: по `http://IP:порт` его просто нет. На iOS вдобавок
нужен `requestPermission()` строго из обработчика **click** (на `change`
у галочки Safari местами не считает это жестом) и синхронно, до первого await.

**Координаты на Android.** Слой управления обязан жить в координатах
`visualViewport`. `position:fixed; inset:0` даёт коробку layout-вьюпорта, а
касания приходят в visual-вьюпорте; пока видна адресная строка, это разные
системы, и сверху остаётся мёртвая зона под 150 px. `vh` в CSS для этого не
годится — это высота с убранной строкой.

**Gzip через центральный прокси.** Он ходит к апстриму по HTTP/1.0, а nginx
жмёт только с 1.1. Нужны `proxy_http_version 1.1` в блоке домена и
`gzip_http_version 1.0` у себя. Но `Connection ""` ради этого **ломает
вебсокет** — для `/ws/` отдельный `location` со своим `Connection: upgrade`.

**Резолв апстримов в nginx.** Имя контейнера резолвится один раз при старте;
после пересборки адрес меняется, и запросы уходят чужому сервису (у нас так
`/api/` начал отдавать пустые 404 от realtime). Лечится `resolver 127.0.0.11`
и именем через переменную.

**Кэш html.** Был `max-age=300`, и браузер полчаса показывал вчерашнюю сборку —
проверки врали. Сейчас `no-cache`: не запрет, а требование переспросить.

**Порядок узлов в звуке.** Коррекция под телефонный динамик (highshelf +
компрессор) должна стоять ДО подводного lowpass, иначе возвращает ровно то, что
фильтр срезал. И применяться только на телефоне: на десктопе компрессор
сплющивает динамику, музыка «орёт» и не реагирует на ползунок.

**Отладка звука.** На паузе `AudioContext` усыплён, `currentTime` стоит, и все
`setTargetAtTime` замирают — параметры выглядят застрявшими, хотя код цел.

**Замеры производительности.** Тайминги в браузере недостоверны: разгон GPU и
throttling давали противоречивые знаки в трёх прогонах подряд. Мерить надо
детерминированное — `renderer.info.render.calls/triangles`, число кадров с
захватом. И фиксировать уровень: у демо-уровней разная сцена.

## Открытые вопросы

- **`realtime` ест ~1.3% процессора вхолостую.** Таймер рассылки при нуле комнат
  не заводится (это видно по коду), значит это базовая стоимость процесса Node
  либо что-то ещё периодическое. Не разобрано.
- **Счёт присылает клиент.** Подделать результат тривиально — это неизбежно,
  пока сервер не считает физику сам (третий уровень сетевой игры).
- **PIN не пароль.** Защищает от случайной путаницы с именами, не более.
- **Комнаты привязаны к уровню**, кода комнаты нет.
